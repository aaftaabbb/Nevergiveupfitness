# Never Give Up Fitness

Gym website and owner admin panel for **Never Give Up Fitness**, Tungarphata, Vasai (E), Palghar.

- Public site: landing page with services, programs, trainer, pricing, café, FAQ, map and a free trial enquiry form.
- Admin panel: members, plans, payments, attendance, enquiries and a dashboard, behind a single owner login.
- Runs on the Vercel free tier with MongoDB Atlas free tier. No paid services.

Built with Next.js 16 (App Router), React 19, Tailwind CSS 4, TypeScript, Mongoose and Zod.

## Requirements

- Node.js 20 or newer
- A MongoDB Atlas free tier cluster
- A free Vercel account for hosting

## Local setup

```bash
npm install
cp .env.example .env.local   # then fill in MONGODB_URI and SESSION_SECRET
npm run seed                 # creates the owner account, plans and demo data
npm run dev                  # http://localhost:3000
```

Generate a session secret with:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('base64'))"
```

### Seed script

```bash
npm run seed                    # plans, demo members, payments, attendance, enquiries
npm run seed -- --clean         # wipe all gym data, keep only the owner and plans
npm run seed -- --force         # also resets the owner password
npm run seed -- --clean --force # clean everything and reset the owner password
```

The owner username and password come from `ADMIN_USERNAME` and `ADMIN_PASSWORD` in `.env.local`.
Change them before seeding a real gym and remove `ADMIN_PASSWORD` from the file afterwards.

**Go-live checklist:** run `npm run seed -- --clean --force` to drop every demo member, payment,
attendance entry, note and enquiry, set a final owner password through `ADMIN_PASSWORD`, and reset
the four plan prices from the admin panel afterwards. `--clean` also puts the plan prices back to
their seed defaults, so set the real prices last.

## Environment variables

| Variable | Used by | Notes |
| --- | --- | --- |
| `MONGODB_URI` | Server and seed | Atlas connection string. |
| `MONGODB_DB` | Server and seed | Database name. Optional, defaults to `never-give-up-fitness`; wins over the path in the URI so `authSource=admin` keeps working. |
| `SESSION_SECRET` | Auth | Signs the admin JWT. Changing it logs the owner out. |
| `ADMIN_USERNAME` | Seed | Owner login name. |
| `ADMIN_PASSWORD` | Seed | Owner login password, bcrypt hashed. |
| `NEXT_PUBLIC_SITE_URL` | Metadata, sitemap | Production domain, no trailing slash. |

## How the admin panel is protected

- `src/proxy.ts` does an optimistic cookie check on `/admin` pages and redirects to
  `/admin/login`. Next.js 16 replaced `middleware.ts` with `proxy.ts`.
- Every page and API route under `/admin` and `/api/admin` verifies the JWT server side, so
  removing the cookie by hand gets nothing.
- Passwords are bcrypt hashed. Login is rate limited per IP.
- The panel is blocked from search engines in `src/app/robots.ts` and marked `noindex` in its
  metadata.

## Notable implementation decisions

- **All dates are IST.** Vercel runs on UTC, so "today" is always derived in `Asia/Kolkata` in
  `src/lib/dates.ts`. Attendance days are stored as `YYYY-MM-DD` strings for that reason.
- **Plans are data, not code.** Membership expiry is calculated from the plan's `months`, so prices
  and durations can change in the admin panel without a deploy.
- **Public pricing never 500s.** `src/lib/dal/public.ts` swallows database errors and the pricing
  page falls back to a call us message.
- **Rating limiters are process local.** Good enough for a single gym, but on multiple Vercel
  instances the counter is per instance. Move it to Mongo or Upstash Redis if abuse becomes a
  problem.

## Deploying to Vercel

1. Push the project to a GitHub repository. `.env.local` is gitignored, so the Atlas URI and the
   session secret stay out of git.
2. Import it in Vercel. The framework preset and build command are detected automatically.
3. Add `MONGODB_URI`, `MONGODB_DB`, `SESSION_SECRET` and `NEXT_PUBLIC_SITE_URL` under
   **Project → Settings → Environment Variables** for Production, Preview and Development.
   `ADMIN_USERNAME` and `ADMIN_PASSWORD` are **not** needed on Vercel; the owner account is created
   in the database by the local seed run.
4. Deploy. Vercel gives a `*.vercel.app` domain; add a custom one under
   **Project → Settings → Domains** if you want `yourdomain.com`.
5. Set `NEXT_PUBLIC_SITE_URL` to the final domain and redeploy, so canonical tags, the sitemap and
   Open Graph URLs use the real host.
6. Verify `/`, `/pricing`, `/contact`, `/admin/login`, `/robots.txt` and `/sitemap.xml`.

### Atlas network access

Vercel serverless functions do not have static outbound IPs, so the Atlas IP access list has to stay
open to `0.0.0.0/0`. Keep authentication on (the free tier requires a database user with a password)
and never put the connection string in client-side code. This project only reads the URI on the
server, in `src/lib/db/mongoose.ts`.
